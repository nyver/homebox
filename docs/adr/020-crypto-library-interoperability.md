# ADR-020: Crypto Library Interoperability

Status: accepted for protocol versions 1 and 2

## Decision

Every cryptographic primitive used across the server/client boundary comes from a mature, independently maintained library on each platform. This project implements no primitive itself (no hand-written AEAD, key exchange, KDF, or hash) and no custom wire protocol for cryptographic handshakes.

## Library inventory

| Purpose | Go | Dart/Flutter |
|---|---|---|
| Secure Transport (ADR-008) | `crypto/tls` (stdlib) | `dart:io` TLS (BoringSSL, bundled with the Dart SDK on every platform) |
| Server identity signing | `crypto/ecdsa` (P-256), `crypto/x509` (stdlib) | n/a (server-only); client-side verification uses only `dart:io` certificate parsing + `package:crypto`'s SHA-256 |
| Account/device key certification (ADR-021) | `crypto/ed25519` (stdlib) verifies certificates as defense in depth | `package:cryptography` (Ed25519, HKDF-SHA256) derives the Account Identity and signs/verifies device keys |
| Password hashing | `golang.org/x/crypto/argon2` | n/a (server-only) |
| File AEAD / key wrapping (E2EE) | n/a (server never decrypts) | `package:cryptography` (XChaCha20-Poly1305, X25519, HKDF-SHA256, Argon2id) — see ADR-010/011/012/013 |
| Secure key storage | n/a | `flutter_secure_storage` (Windows Credential Manager / Android Keystore backed) |

## Interoperability evidence

- Secure Transport: both `crypto/tls` and Dart's BoringSSL-backed TLS are independent, mature TLS 1.3 implementations validated against the same public standard; `internal/securetransport/transport_test.go` proves a real `tls.Dial` handshake against the server's certificate, `internal/httpapi/httpapi_test.go` proves a full authenticated request cycle plus a raw-wire scan confirming no secret ever appears outside the TLS record layer, and `client/test/transport/pinned_http_client_test.dart` proves a real Dart `HttpClient` handshake against a certificate fixture generated by the actual Go code (not hand-crafted), including a positive and a negative (mismatched-fingerprint) case. This pairing is what caught the Ed25519/Dart incompatibility recorded in ADR-008 before it reached a release build.
- E2EE file/key primitives: fixed test vectors in `client/test` pin XChaCha20-Poly1305 chunk framing, key-envelope wrapping, and Recovery Secret derivation so a future change to the underlying library is caught immediately if it silently changes output for the same input.
- Device-key authentication: `internal/deviceauth/certificate_test.go` and `client/test/account_identity_test.dart` cover the same canonical signed fields on both sides; the HTTP integration test rejects both a tampered signature and a valid signature from a conflicting Account Identity, while the provisioning-v2 test proves that removing or changing the certificate binding prevents unwrap.
- Nothing in `internal/` imports or can reach the client's E2EE decryption code (`client/lib/core/e2ee/*`); the server module graph has no dependency edge into it, which is the architectural enforcement §38.3A calls for ("server packages не импортируют client E2EE decryptor").

## Consequences

- No dependency in this project's own code is "cryptography we wrote"; anything resembling a primitive is a call into one of the libraries above.
- If a future milestone needs a primitive not covered here (e.g. a real Noise implementation becomes viable — see ADR-008's reconsideration note), it requires its own ADR and the same interoperability bar: mature, independently maintained on both platforms, validated with test vectors before use.
